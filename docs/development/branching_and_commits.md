# Branching and commits

Keep `main` releasable at its documented maturity. Use short focused branches,
reviewed pull requests, and meaningful conventional commits: `feat`, `fix`,
`test`, `docs`, `refactor`, `perf`, `build`, `ci`, `chore`, or `security`.

Prefer many coherent commits over one opaque dump, but do not generate empty,
one-line, or formatting-only spam. Every commit should have a clear purpose and
leave the repository understandable. Physics/rules commits include regression
tests; UI commits include localization/accessibility; dependency/asset commits
include license provenance.

Before handoff update `what_changed.md`, status, known issues, phase status,
test matrix, and continuation cursor with exact next file/task.
