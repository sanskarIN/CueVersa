# Suggestion triage process

1. Confirm scope, originality, conduct, and duplicate status.
2. Identify the user need separately from the proposed solution.
3. Assess gameplay value, deterministic/rule impact, ranked fairness,
   accessibility, localization, privacy/security, platform policy, performance,
   maintenance, asset/license provenance, and monetization ethics.
4. Label as needs information, declined with reason, future, designed, ready,
   in progress, or shipped.
5. Large accepted work receives an issue/spec, owner, acceptance criteria,
   tests, docs, and release target.

Maintainers may decline ideas that copy protected identity, fragment physics,
create pay-to-win, enable wagering/dark patterns, require unjustified sensitive
data, or exceed sustainable scope. Decisions should be respectful and
evidence-based.
